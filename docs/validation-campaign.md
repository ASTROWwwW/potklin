# 0.4 experimental validation campaign

Implemented incremental capabilities: compare-and-swap text edits (explicit permission, trusted workspace), dependency inventory (not CVE scanning), local embedding index via Ollama, verifier-driven fast/deep retry, local Tk GUI, optional UI Automation structural observation, isolated synthetic Chromium interaction, randomized DAG stress tests, seeded multi-tool and exact-answer reasoning evaluations, and verified synthetic trajectory export for human review.

Scope: browser test uses a developer-owned fixture and blocks routed requests; it is not a general browser agent or OS-level network sandbox. UIA observes controls without editable values; it does not implement general mouse/keyboard control. No general red-team exploitation, arbitrary execution, remote GitHub mutation, LoRA training, inference-engine changes, or actual accelerator scheduling. The scheduler is a policy prototype. Filesystem checks are not an OS sandbox and are not race-proof. Do not use on hostile workspaces. Model completion is not proof of task success.

Validation order: syntax, unit tests, offline fixtures, randomized stress, optional browser/desktop checks, local model smoke/integration, multi-step and seeded deep evaluations, exact reasoning, optional semantic embedding test. Run all independent stages even if another stage fails; report failures/skips separately. Default deep evaluation uses 100 distinct seeded cases in both reasoning modes; exact reasoning uses 100 more in both modes. These are synthetic task families, not a comprehensive intelligence or real-world red-team benchmark. Hardware telemetry is observational only. Optional packages and browser installation require network access. No administrator privileges required. No automatic model downloads or hardware modifications.
