# V7 / prototype 0.2

Developer-authored manifests are static; registry validates correspondence. Mission runner permits selected read-only tools, up to 12 actions, rejects duplicates and malformed/unavailable actions, records metadata in SQLite, and returns model summaries as unverified. Tool observations are bounded and treated as untrusted. This is not an OS sandbox; use disposable trusted workspaces. No autonomous external scanning, exploitation, arbitrary shell execution, or model-created mods. AST review identifies local Python source patterns and does not prove vulnerabilities. Windows status enumerates visible top-level windows and matches process executable basename, not full UI readiness or application identity attestation. Launch and observation are distinct; optional probe uses an explicit launch flag. Full UI Automation, recursive planning, concurrent tool execution, semantic memory, runtime optimization and real red-team laboratory workflows remain pending. Tests must be run locally or in CI before claiming success.

## Run
- python -m unittest discover -s tests -v
- python -m potklin mods
- python -m potklin --workspace <fixture-directory> mission "List files then review Python" --mods filesystem cyber
- python -m scripts.v7_probe --model <actual-local-tag> --repeats 10
- python -m scripts.windows_probe --app discord --launch

The mission probe independently checks required observed tools and expected fixture facts; model completion alone is not a pass. No model downloads or hardware settings required.
